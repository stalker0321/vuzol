# Задание Гроку

Прочитай полностью `PROJECT_AGENTS_IMPLEMENTATION_PLAN.md` рядом с этим файлом. Это архитектурный контракт и критерии сдачи, а не предложение переписать Вузол целиком.

Рабочий каталог: `/home/vodkolyan/vuzol-afterword-stabilization`. Сначала проверь актуальные инструкции репозитория и состояние git: после написания плана они могли измениться.

Нужно добавить агента-руководителя поверх существующего исполнения. Он ведёт согласованную цель, выбирает следующие небольшие пакеты, получает результаты и продолжает работу. Sequencer остаётся единственным управляющим внутри пакета. Общий Telegram inbox — последующая точка входа в тот же механизм, не второй оркестратор.

Порядок работы:

1. Выполни этап 0. Незакоммиченные изменения принадлежат владельцу. Если владелец ещё не сохранил/не разрешил сохранить baseline, сначала дай конкретный список и запрос решения; не делай reset/stash и не начинай переписывать эти файлы.
2. После сохранённого baseline и подтверждённой feature branch выполни этап 1, затем этап 2. Приоритет — законченный вертикальный сценарий, отказоустойчивость и сохранение legacy, а не число новых tools.
3. На этапе 2 остановись с отчётом для проверки владельцем. Этапы 3–5 описывают направление, но не входят в эту ночную итерацию без отдельного указания.
4. Используй fake provider/Telegram и выделенную PostgreSQL test DB. Реальные model calls, Telegram mutations, production, host installs и внешние deploy не разрешены этим заданием.
5. Feature off по умолчанию. Не обходи approval, evidence, scope/version checks. Не подставляй owner ID вместо agent principal. Не скрывай сбои baseline и skipped integration tests.

Разрешение коммитить изменения в согласованной feature branch не означает разрешение публиковать их или менять работающие сервисы. Если полномочий/данных не хватает — остановись с конкретным blocker, не импровизируй новый продуктовый контракт.

Итог: коммиты по этапам, точные команды и результаты тестов, trace сквозного сценария, список миграций, инструкция включения/отключения в тестовой среде и честный список недоделанного. Отдельно покажи, что после рестарта между пакетами работа продолжается один раз, а после pause/отзыва прав старый ответ модели ничего не запускает.
